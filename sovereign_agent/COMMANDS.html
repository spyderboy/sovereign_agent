▶

Stop everything

First move for almost any problem. Ctrl-C is not enough.

Ctrl-C kills the foreground process but leaves supervisor and worker alive, and they keep resetting your repo underneath you. Kill the supervisor first or it just relaunches the worker.

pkill -9 -f supervisor.sh
pkill -9 -f work.py
sleep 1
ps aux | grep -E '[w]ork.py|[s]upervisor.sh' | wc -l

must print 0

Free the model from memory too, if you're switching models or need the RAM:

ollama stop qwen2.5-coder:14b
ollama ps

ollama ps should come back empty — otherwise it holds ~9–21 GB for 30 minutes

▶

Clean restart (the standard block)

Any time a run has been interrupted, or before launching.

Run Stop everything first. Then:

cd ~/Code/witches_bricks
find .git -name '*.lock' -delete
git checkout -f main
git clean -fd
git for-each-ref --format='%(refname:short)' 'refs/heads/task-*' | xargs -r git branch -D
git status --short
git branch

git status --short must print NOTHING — a ?? line is as fatal as a modified file

git branch must show only main

Why each line is there. checkout -f restores tracked files but leaves untracked ones, so a file a failed task wrote survives every clean and blocks every start — that's what git clean -fd is for. The refspec must be quoted or zsh glob-expands it, fails with "no matches found", and deletes no branches at all.
▶

Launch a run

After a clean restart. Always from sovereign_agent, never the project.
cd ~/Code/Xanadu/sovereign_agent
SOVEREIGN_PROFILE=gemma26 ./supervisor.sh ~/Code/witches_bricks --features-only

Overnight — caffeinate -i blocks idle sleep, but not lid-close sleep. Leave the lid open.

cd ~/Code/Xanadu/sovereign_agent
SOVEREIGN_PROFILE=gemma26 caffeinate -i ./supervisor.sh ~/Code/witches_bricks --features-only

Read the banner before walking away. It is the receipt for everything you just committed:

Banner lineWhat it proves
Loaded N always-include context file(s)your config edit landed — if N is wrong, the commit didn't
config: profile 'gemma26' | …which ladder is actually running
N locked pathsthe locked contract is in force
▶

It's looping / scrolling banners forever

Same startup text over and over, no attempts happening.
Read the FIRST lines of the scroll, not the last. work.py refused a precondition and exited; the reason is one line near the top and it names the file. Everything after is the supervisor relaunching.

The three causes, in order of frequency:

MessageFix
Working tree is dirtyClean restart block — note a ?? untracked line counts
On branch 'task-…', not 'main'Clean restart block — deletes leftover task branches
index.lock / packed-refs.lock existsfind .git -name '*.lock' -delete

Stop, then run the clean restart block. If the harness is current, it stops itself after three sub-10-second exits instead of spinning.

▶

How did the run go?

First thing in the morning, or after any long run.

Parked tasks first. These stopped for a reason no model could fix, and each entry names the file actually at fault:

cd ~/Code/witches_bricks
cat logs/needs_review.md

Then progress and per-task outcomes:

cd ~/Code/witches_bricks
echo "$(grep -c '^- \[x\]' ROADMAP.md) / $(grep -cE '^- \[[ x]\]' ROADMAP.md) done"
python3 -c "
import json
rows=[json.loads(l) for l in open('logs/velocity.jsonl')][-15:]
for r in rows:
    print(f\"{r.get('outcome','?'):12} {r['attempts']:2}a {r['duration_s']:7.0f}s  {r['task'][:52]}\")"
outcomemeaning
donemerged. attempts=1 is the healthy case
needs_reviewparked — failures named no file it wrote
budgethit the 3600s hard ceiling and was skipped

Is it still alive? The supervisor only logs at batch boundaries, so silence there proves nothing:

cd ~/Code/witches_bricks
ls -l logs/task_traces.jsonl; sleep 10; ls -l logs/task_traces.jsonl

size changed = running · unchanged = dead or stuck

▶

A task is stuck or escalating

Same error repeating, or climbing the model ladder.

Ask in this order. Getting the order wrong is what turns five minutes into six hours.

1Whose failure is it? If no error names a file this task wrote, the cause is an earlier merge or an unsatisfiable gate. A bigger model cannot reach it. Look for the ⚠ No error names a file this task wrote line.
2Read the record, not the console. The console truncates to the first error at 100 characters and routinely hides the cause.
3Repetition means diagnose; variation means escalate. The same error every attempt is a constant in the environment. Different errors each time is a model out of its depth.
cd ~/Code/witches_bricks
tail -60 logs/$(date +%Y-%m-%d)-work.log
fileholds
logs/<date>-work.logfull validator output for every attempt
logs/task_traces.jsonlprompt + raw model output per attempt
logs/needs_review.mdparked tasks with diagnosis
logs/velocity.jsonlone line per task outcome
▶

Change a project file while working

Editing config, ROADMAP, API.md, or fixing a merged file by hand.
The ordering rule. A git checkout -f must never appear AFTER an edit and BEFORE its commit. work.py runs checkout -f and clean -fd between every task, so an uncommitted edit is discarded within seconds. Never edit a project file while a run may be live.

Safe order — kill → clean → edit → commit in the same block → verify → launch:

cd ~/Code/witches_bricks
<your edit here>
git add -A
git commit -m "what changed"
git show HEAD:<the file> | <print the changed value>

Example — proving a config edit actually landed:

cd ~/Code/witches_bricks
git show HEAD:.sovereign_config.json | python3 -c "import json,sys; print('COMMITTED:', len(json.load(sys.stdin)['context_always_include']))"

on disk but not in HEAD does not exist as far as the next task is concerned

▶

Switch models / A-B test

Trying a different ladder without touching work.py.

Model choice lives in profiles/<name>.toml. Copy a file, change two lines, run it:

cd ~/Code/Xanadu/sovereign_agent
ls profiles/
SOVEREIGN_PROFILE=qwen25  ./supervisor.sh ~/Code/witches_bricks --features-only

One-off override without editing anything — a real env var beats the profile:

TIER1_MODEL=gemma4:26b SOVEREIGN_PROFILE=qwen25 ./supervisor.sh ~/Code/witches_bricks --features-only
Precedence, highest first: exported env var → sovereign_agent/.env (auto-loaded, easy to forget it exists) → profiles/*.toml → built-in defaults. If a profile seems ignored, check .env first — it should hold keys and endpoints only, not models.
grep -nE "^TIER|^PLANNER|^ADVISOR|^MODEL_PARAMS" ~/Code/Xanadu/sovereign_agent/.env

ideally prints nothing — model lines there silently outrank every profile

▶

Protect harness changes

After anyone edits sovereign_agent/. Do it immediately.
Xanadu is a git repo too. A git checkout -f plus git clean -fd in it reverts tracked files and deletes untracked ones outright. On 2026-08-10 that wiped a day of harness fixes and six helper scripts with no stash and nothing recoverable in fsck.
cd ~/Code/Xanadu
git status --short
git add -A
git commit -m "harness: what changed"

Before any destructive git command there, see what you'd lose:

cd ~/Code/Xanadu
git clean -nd

-n is a dry run: lists what -fd would delete, deletes nothing
